    პაკეტების მართვა: apt და dpkg¶

    გარემო

    წაკითხვადი ბრძანებების გამოტანა (dpkg -S, apt-mark showhold) რეალური გაშვებიდანაა (Ubuntu 24.04-ზე დაფუძნებული სისტემა). ბრძანებები, რომლებიც სისტემას ცვლის (apt install, apt upgrade), საჭიროებს sudo-ს და ამ გარემოში არ გაშვებულა: მათი გამოტანა მონიშნულია, როგორც მაგალითი.

    1. სასწავლო მიზნები¶

    • განმარტოთ პაკეტი, რეპოზიტორია და განსხვავება apt-სა და dpkg-ს შორის;
    • განვაახლოთ პაკეტების სია და სისტემა (apt update, apt upgrade);
    • დავაყენოთ, წავშალოთ და მოვძებნოთ პაკეტი;
    • გავიგოთ, რომელ პაკეტს ეკუთვნის ფაილი (dpkg -S);
    • გამოვასწოროთ ხშირი შეცდომები (lock, Unable to locate package, გატეხილი დამოკიდებულებები).

    2. შესავალი¶

    Debian/Ubuntu-ზე პროგრამებს ვაყენებთ პაკეტებით: არქივი, რომელიც შეიცავს ფაილებს, მეტამონაცემებს და დამოკიდებულებებს. პაკეტების მართვა არის ყოველდღიური ადმინისტრირება: nginx-ის, Docker-ის, ბაზების დაყენება და უსაფრთხოების განახლებები. ჩვენს ლაბორატორიულ Task-ებშიც ეს გამოვიყენეთ (მაგ. System Update).

    3. თეორიული ახსნა¶

    apt და dpkg¶

    ხელსაწყო დონე რას აკეთებს
    dpkg დაბალი ერთ .deb ფაილს აყენებს/ხსნის და ითვლის ლოკალურ ბაზას. დამოკიდებულებებს თავად არ ჩამოტვირთავს
    apt მაღალი რეპოზიტორიებიდან ჩამოტვირთავს, დამოკიდებულებებს ხსნის და dpkg-ს იყენებს 
    flowchart LR
    R["რეპოზიტორია<br>(სერვერი)"] -->|apt update: სიის ჩამოტვირთვა| L["ლოკალური სია"]
    L -->|apt install| D["ჩამოტვირთვა .deb"]
    D -->|დამოკიდებულებები| DP["dpkg: დაყენება"]
    DP --> DB["დაყენებული<br>პაკეტების ბაზა"]

    რატომ ორი ნაბიჯი (update და upgrade): apt update მხოლოდ სიას ანახლებს (რა ვერსიებია ხელმისაწვდომი), არაფერს აყენებს. apt upgrade უკვე დაყენებულ პაკეტებს განაახლებს ამ სიის მიხედვით. update-ის გარეშე apt ძველ სიას ხედავს.

    usrmerge და dpkg -S¶

    თანამედროვე Ubuntu-ზე /bin არის სიმბოლური ბმული /usr/bin-ზე (იხ. FHS). dpkg ფაილის ბილიკს ზუსტად ადარებს: ამიტომ dpkg -S /usr/bin/ls პოულობს, ხოლო dpkg -S /bin/ls ვერ პოულობს, თუმცა ორივე ერთ ფაილზე მიუთითებს.

    4. ტექნიკური მაგალითები¶

    წაკითხვადი ბრძანებები (რეალური გამოტანა):

    dpkg -S /usr/bin/ls
dpkg -S /bin/ls
apt-mark showhold

    coreutils: /usr/bin/ls
dpkg-query: no path found matching pattern /bin/ls

    apt-mark showhold ცარიელია, როცა არცერთი პაკეტი არ არის დაბლოკილი.

    მართვა (მაგალითი, საჭიროებს sudo-ს):

    sudo apt update
sudo apt upgrade
sudo apt install htop

    Reading package lists... Done
Building dependency tree... Done
The following NEW packages will be installed:
  htop
Setting up htop ...

    5. ბრძანებები და კოდი¶

    ბრძანება რას აკეთებს რატომ
    sudo apt update პაკეტების სიის განახლება ახალი ვერსიების სანახავად
    sudo apt upgrade დაყენებულების განახლება უსაფრთხოების გასწორებები
    sudo apt install პაკეტი დაყენება დამოკიდებულებებით პროგრამის მიღება
    sudo apt remove / purge წაშლა / წაშლა კონფიგებითურთ purge ასუფთავებს /etc-შიც
    sudo apt autoremove აღარ საჭირო დამოკიდებულებები დისკის გათავისუფლება
    apt search სიტყვა, apt show პაკეტი ძებნა და ინფორმაცია სწორი პაკეტის პოვნა
    dpkg -l, dpkg -L პაკეტი დაყენებულების სია / პაკეტის ფაილები რა გვაქვს და სად
    dpkg -S /გზა რომელ პაკეტს ეკუთვნის ფაილი წარმომავლობა
    sudo apt-mark hold პაკეტი ვერსიის დაბლოკვა არასასურველი განახლების თავიდან აცილება
    sudo apt --fix-broken install გატეხილი დამოკიდებულებების გასწორება შეწყვეტილი დაყენების შემდეგ

    6. პრაქტიკული სავარჯიშოები¶

    ნაწილი A: კითხვა (უსაფრთხო):

    dpkg -S /usr/bin/ls
dpkg -S /bin/ls                 # რატომ ვერ პოულობს?
dpkg -L coreutils | head -5     # პაკეტის ფაილები
apt-mark showhold
apt show coreutils 2>/dev/null | head -3

    ნაწილი B: დაყენება (ლაბორატორიულ VM-ზე, sudo):

    sudo apt update
sudo apt install tree
tree -L 1 /etc | head
sudo apt remove tree

    7. მოსალოდნელი შედეგი¶

    ნაწილი A: dpkg -S /usr/bin/ls აბრუნებს coreutils: /usr/bin/ls, ხოლო /bin/ls აბრუნებს no path found matching pattern /bin/ls. ეს შეცდომა არ არის: ეს usrmerge-ის შედეგია (§3). ბრძანება apt show ბეჭდავს Package, Version და სხვა ველებს (გამოტანა ვერსიების მიხედვით განსხვავდება). ნაწილი B-ს გამოტანა მაგალითია.

    8. პრობლემების მოგვარება¶

    სიმპტომი მიზეზი გამოსწორება
    Could not get lock /var/lib/dpkg/lock-frontend სხვა apt/განახლების პროცესი მუშაობს დაელოდეთ ან ნახეთ sudo lsof /var/lib/dpkg/lock-frontend; ნუ წაშლით lock-ს ბრმად
    Unable to locate package X სია ძველია ან სახელი არასწორია sudo apt update, შეამოწმეთ apt search X
    dpkg -S /bin/ls ვერ პოულობს usrmerge: ბილიკი /usr/bin/ls გამოიყენეთ readlink -f /bin/ls და მერე dpkg -S
    Packages not valid yet / Release file is not valid yet სისტემის საათი ჩამორჩენილია sudo chronyc makestep (იხ. პრობლემების ცნობარი)
    unmet dependencies / დაყენება შეწყდა გატეხილი დამოკიდებულებები sudo apt --fix-broken install, შემდეგ sudo dpkg --configure -a
    განახლებამ სერვისი გააფუჭა ახალი ვერსია შეუთავსებელია sudo apt-mark hold პაკეტი და გამოსასწორებლად ვერსიის დაბრუნება

    9. ცოდნის შემოწმება¶

    1. რა განსხვავებაა apt update-სა და apt upgrade-ს შორის?

    update მხოლოდ პაკეტების სიას ანახლებს; upgrade უკვე დაყენებულ პაკეტებს განაახლებს ამ სიით.

    2. რით განსხვავდება apt dpkg-სგან?

    dpkg ერთ .deb ფაილთან მუშაობს დამოკიდებულებების ჩამოტვირთვის გარეშე; apt რეპოზიტორიიდან იღებს და დამოკიდებულებებს ხსნის.

    3. რატომ ვერ პოულობს dpkg -S /bin/ls, თუმცა /usr/bin/ls პოულობს?

    /bin ბმულია /usr/bin-ზე (usrmerge); dpkg ბაზაში ბილიკი /usr/bin/ls-ია.

    4. რას აკეთებს apt-mark hold?

    კონკრეტულ პაკეტს განახლებისგან ბლოკავს.

    5. რა უნდა ვქნათ, თუ apt lock-ს უჩივის?

    დაველოდოთ სხვა apt/dpkg პროცესის დასრულებას; lock-ის ფაილს ბრმად არ ვშლით.

    10. შეჯამება¶

    • apt მაღალი დონეა (დამოკიდებულებები), dpkg დაბალი (ერთი .deb).
    • update სიას ანახლებს, upgrade პაკეტებს.
    • dpkg -S პოულობს მფლობელ პაკეტს; usrmerge-ის გამო გამოიყენეთ /usr/bin/....
    • ხშირი შეცდომები: lock, ძველი სია, გატეხილი დამოკიდებულებები, საათის ჩამორჩენა.
